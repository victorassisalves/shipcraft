## Item 17: commit-msg judgment and post-commit closure

- Manual config uses parallel pre-commit, a command without priority, commit-msg and post-commit; init's route selection is outside this item.
- Official lefthook v1.11.13 launchers end in call_lefthook for each event with "$@". Offline LEFTHOOK_BIN dispatch accepts message paths with spaces; it does not simulate concurrency or installation. The final-index case measures the resulting index directly.
- Judgment writes a Shipcraft marker without changing tree/index locks; nonexistent message paths are accepted and ignored.
- RED index/GREEN tree cannot close; GREEN index/broken tree closes. Unstaged files do not affect judgment.
- Locked-test refusal removes an earlier marker. A nonempty directory blocking marker creation refuses without closure.
- Normal closure creates a child commit containing only closed locks, with the contracted message; CI accepts it. Amend and detached HEAD preserve identity/advance correctly.
- A new green lock in the first commit refuses as red-already-passes, without marker/commit. First RED then GREEN closes in a separate child, with HEAD@{1} pointing to RED.
- Commit --only uses its temporary index; closure never includes the original index. Entries staged after judgment stay intact except updated lock entries.
- Divergent worktree lock bytes remain untouched with a one-line warning; matching old HEAD bytes are updated.
- Two actual RED markers close together; lock names in the message are in bytewise ascending order joined by ", " (item 49).
- Linked worktree markers use git-path shipcraft/close; common markers stay intact; metrics use git-common-dir.
- Wrong tree/HEAD, aborted commits and absent reflog remove stale markers, leave locks open and warn; equal tree alone is insufficient.
- Missing/invalid markers (including non-UTF-8 bytes) are silent success and leave HEAD intact.
- Merge/cherry-pick/revert/rebase state recognized by git status removes markers without closing.
- Signing/index-lock failures before ref update preserve HEAD/index/files/marker, exit 0 and suggest shipcraft close; retry closes.
- A git wrapper moving HEAD just before update-ref checks compare-and-swap and marker preservation; this assumes plumbing through the git executable.
- Closure appends exactly one passed close row per lock that actually closes, naming its lock id and closing commit, without rewriting existing metric bytes. A call closing nothing appends no row. A GREEN commit with hooks appends one hook row plus those close rows, and nothing else. Closure runs no hooks and changes no non-lock blobs; repeated calls without markers are silent.
- Eight lefthook main/local names are byte-protected for staged creation/change, including comments, CRLF and flow YAML; init layout/priority rules stay in items 15b/15c.
- Ignored support modules enter the judged copy; untracked, unignored modules do not.
- A wrapper replacing the index destination after successful update-ref leaves the closed HEAD, exits 0 and gives a Git repair command; same executable-wrapper limitation.
- Historical RED checks: 30/30 failed before the new CLI; the first-commit split produced 31 IDs and two focused failures. Later checks after the first failure awaited GREEN.
- Real SSH signatures use disposable ed25519 keys and allowedSignersFile paths with spaces under the case TMPDIR. GIT_CONFIG_COUNT=1/2 and repository-only controls require signed GREEN and child commits plus git verify-commit success; no user keys.
- Review #65: both environment-config signing cases failed only on the unsigned child, while repository-only signing passed; 34 IDs total.
