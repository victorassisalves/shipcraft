## Item 21: release and installation

- No publication: scripts run in a fresh Git repository with local bare origin. gh/cargo/git ls-remote/uname/sysctl are PATH stubs; curl/wget/brew/npm are blocked.
- gh simulates release view JSON (tagName/id/url), jq, download pattern/directory and create URL output. Tar archives and SHA256SUMS are real, judged by tar/shasum.
- Version works outside a project and with invalid TOML: X.Y.Z and 12 hexadecimal commit characters or no-git.
- Version comparison reads Cargo at runtime: equal/previous-major minima pass, increases in each component refuse, leading-zero components compare numerically. Cases do not fix init's version literal.
- X.Y.Z/vX.Y.Z release inputs with --local-build build both targets from a pinned clean checkout, run one all battery on host architecture (ARM/common, Intel/prefix), and disclose the untested other target.
- Partial/prerelease/extra/double-prefix/nonnumeric versions, dirty tree, mismatched Cargo, local-only HEAD and existing remote tag refuse without publishing. Remote main/tag query errors never become absence.
- A cargo wrapper moves source HEAD/content mid-build; both builds, battery and tag must keep the pinned commit.
- Packages contain only root executable shipcraft; two tar.gz assets, one correct checksum line per archive.
- Injected build/battery failures must reach their target step before refusing.
- A create response identifying the new resource followed by error deletes only that resource. Missing response permits no deletion and gives three-line inspection guidance.
- Installation outside a repository fixes repository and resolved tag once, even if latest changes later. A wrong checksum for the other architecture does not block the selected archive.
- Explicit SHIPCRAFT_REPO/tag are fixed on every gh call/download. Rosetta arm64 capability selects ARM; Intel selects Intel; Linux requests cargo install --path nucleo.
- Wrong/missing/duplicate selected checksum preserves prior bytes/inode.
- Extra/nested files, nonexecutable binary, version mismatch, unreadable tar with correct checksum, occupied destination or unwritable directory refuse without losing the previous executable.
- The fake executable records --version and prior inode; successful atomic replacement requires new inode, expected bytes and cleaned temporaries.
- Equal version/checksum preserves inode/mtime with notice; equal version but different local bytes replaces.
- PATH shadowing names the resolved binary and directory that must precede it.
- Remove deletes only the binary, without gh, and gives one-line project/commit guidance.
- ./shipcraft and shipcraft are equivalent archive root members; asset/checksum ordering is unconstrained.
- These orchestration probes do not validate Mach-O, real GitHub or execution of the other target.
