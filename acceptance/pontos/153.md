# Item 153 — Hooks wired by hand

- `v1-153.repro` — With no hook tool and executable shell hooks in `.githooks`, Python init exits zero, creates the config and onboarding files, prints the kept line with both paths, preserves both hook bytes and modes, and retains item 101’s status line.
- `v1-153.pre-custom` — A pre-commit project can keep hand-wired hooks under `core.hooksPath`, leaving the supported block YAML untouched. Status uses the hand-wired line.
- `v1-153.flow` — Hand-wired hooks bypass the flow-style YAML refusal. Status prints the exact hand-wired line, including when a later unsupported lock format causes exit 1.
- `v1-153.foreign-commit` — A foreign commit-msg can be kept when it calls Shipcraft last and post-commit closes. Init and status leave the script unexecuted. Removing post-commit restores the exact three-line refusal with no manual branch.
- `v1-153.two-tools` — A pre-commit and lefthook conflict yields to both hand-wired hooks without modifying either configuration. Status reports hand wiring.
- `v1-153.pre-foreign` — The refusal of a non-launcher commit-msg in a block-style pre-commit project yields to a hand-wired pair.
- `v1-153.lefthook-invalid` — Invalid lefthook YAML stays byte-identical when init and status recognize the hand-wired pair.
- `v1-153.pre-link` — Init keeps the linked pre-commit configuration and the target’s bytes and mode.
- `v1-153.foreign-post` — The foreign post-commit alone can trigger the hand-wired route when commit-msg has Shipcraft’s own marker and a terminal call.
- `v1-153.two-lefthooks` — A pair of root lefthook files stays intact when the Git hooks prove hand wiring.
- `v1-153.extends` — A lefthook file with `extends` stays intact when Git’s hooks prove hand wiring.
- `v1-153.lefthook-foreign` — An installed commit-msg that is not from lefthook yields when the hand-written pair qualifies.
- `v1-153.symlink` — Both hook links and their executable targets are kept. Leading blanks, a spaced path, mixed quoting, optional `exec`, bare `$1`, trailing space and tabs, and the project-local command word are recognized.
- `v1-153.kept` — The hand-wired route keeps the existing TOML, including its lower minimum and mode, with the existing kept line. A later invalid TOML refusal leaves the fixture unchanged.
- `v1-153.commit` — With the binary on PATH and no lock open, a real Git commit succeeds and records one passed hook row.
- `v1-153.dispatcher` — Both hooks link to one executable dispatcher in `.githooks`; init refuses with the exact Next and no branch, preserving the tree, Git config, target bytes, links and modes, before and after appending the two calls through their hook names. - `v1-153.early-exit` — An earlier `exit` or tab-indented `exec` keeps the refusal with no manual branch.
- `v1-153.operator` — A command after `shipcraft close` (merged from `v1-153.trailing-command`), or a trailing `||`, background operator, or semicolon after the Shipcraft call keeps the refusal with no manual branch.
- `v1-153.cr` — CRLF, a shebang with `-n`, and a BOM before the shebang each prevent hand-wiring recognition.
- `v1-153.comments` — Blank lines and an inline or trailing comment, including non-UTF-8 comment bytes, leave the terminal call under `#!/usr/bin/env bash` valid.
- `v1-153.manual-pre` — The pre-commit launcher refusal keeps its first two lines and existing Next prefix, with the exact Next ending at the rerun, no `, or make ` and no `manually`.
- `v1-153.manual-local` — A root project install, reached through its executable launcher symlink, prints the exact Next with `npx -- shipcraft init` for the rerun, no `node_modules/.bin/shipcraft` and no manual branch.
- `v1-153.only-commit` — The exact custom-path refusal has no manual branch for an absent pair, a missing post-commit, and a nonexecutable post-commit. Init writes nothing.
- `v1-153.rollback` — A file in place of `.shipcraft/` blocks the later core write. Init exits 2, reports rollback, leaves no newly created files and preserves the hooks and Git config.
- `v1-153.check-only` — A missing or longer `--commit-msg` argument, a wrong message parameter, and an `npx --no --` prefix keep the refusal.
- `v1-153.worktree` — The exact refusal has no branch and preserves both trees; after hand wiring, the kept line names the main repository’s hook paths exactly as Git reports them in the linked checkout, preserving the main tree and hook bytes and modes.
