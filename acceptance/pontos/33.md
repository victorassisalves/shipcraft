## Item 33: actionable lock restoration

- Literal command: git restore --staged --worktree --source=HEAD -- with the refused lock's root-anchored :/ pathspec in single quotes.
- Three hook lock refusals retain their first two lines, earlier hint text and run-log code.
- Execute the command from a subdirectory; index and tree bytes must match HEAD afterward.
- During merge, use the first-parent HEAD open lock even when MERGE_HEAD has it closed.
- Two edited locks produce one suggestion for the first refusal; restoring it leaves the other edited.
- Safe names use ASCII letters/digits/dot/underscore/hyphen. Spaces/accents/quotes omit the command for all three refusal types.
- New lock or absent HEAD keeps the next-step hint without command. Missing HEAD blob preserves the legacy cat-file error without a suggestion.
- CI retains the earlier next-step hint without restore command.
- Closed-red uses a valid hook-produced closed lock; manually changing its state tests lock-edited instead.
